# DigitalSub — сайт digitalsub.ru

Лендинг сервиса «сайты и приложения по подписке с правом выкупа»: офер, «как это работает», что делаем, сравнение с разработкой под ключ, тарифы, **калькулятор стоимости**, модель выкупа, FAQ и форма заявки.

## Стек

- **Фронтенд:** статический HTML + CSS + чистый JavaScript, без сборки и фреймворков (`public/`).
- **Бэкенд:** один файл `server.js` на Node.js (только встроенные модули, **ноль npm-зависимостей**). Раздаёт статику и принимает заявки на `POST /api/lead`.
- **Хранение заявок:** файл `data/leads.jsonl` (одна заявка на строку, JSON). В Docker лежит в томе `leads`.
- **Telegram:** если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, каждая заявка дублируется в Telegram.
- Защита формы: honeypot-поле от ботов, лимит 5 заявок за 10 минут с одного IP, ограничение размера запроса, CSP и прочие заголовки безопасности.

## Запуск в Docker

Нужен Docker Desktop (Windows/macOS) или Docker Engine + Compose v2.24+ (Linux).

```bash
cd F:\digitalsub          # или путь к папке проекта
copy .env.example .env    # Windows (на Linux/macOS: cp .env.example .env) — по желанию
docker compose up -d --build
```

Сайт откроется на **http://localhost:8080**.

Полезные команды:

```bash
docker compose logs -f                              # логи (каждая заявка тоже пишется в лог)
docker compose exec web cat /app/data/leads.jsonl   # посмотреть все заявки
docker compose down                                 # остановить (заявки сохраняются в томе)
docker compose up -d --build                        # пересобрать после правок
```

> Если ваша версия Docker Compose ругается на `env_file` (`required`), обновите Docker Desktop или просто создайте файл `.env` (можно пустой) из `.env.example`.

## Запуск без Docker

Нужен Node.js 20+:

```bash
node server.js            # http://localhost:8080
```

Переменные окружения: `PORT` (по умолчанию 8080), `DATA_DIR` (по умолчанию `./data`), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.

## Уведомления в Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Напишите боту любое сообщение (или добавьте его в группу).
3. Узнайте chat_id: откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":...}`.
4. Впишите значения в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   TELEGRAM_CHAT_ID=123456789
   ```
5. `docker compose up -d` — в логе появится «Telegram: включён».

## Калькулятор: как менять цены

**Все цены калькулятора лежат в одном файле: `public/assets/pricing.json`.** После правки выполните `docker compose up -d --build` (без Docker достаточно обновить страницу).

| Поле | Что значит |
|---|---|
| `bases[]` | Основа продукта: `name`, `desc` (подпись), `price` — ₽/мес, `modules` — список id модулей, доступных для этой основы. При смене основы недоступные модули скрываются и сбрасываются. |
| `modules[]` | Модули: `id`, `name` и `price` — сколько ₽/мес добавляет модуль. |
| `groups[]` | Разделы модулей в калькуляторе: `id`, `name`, необязательная подпись `note`. Порядок разделов — как в файле. |
| `modules[].group` | В каком разделе показывать модуль (id из `groups`). |
| `modules[].adBudget` | `true` — под расчётом показывается напоминание, что рекламный бюджет оплачивается отдельно. |
| `modules[].from`, `modules[].note` | Необязательно. `from: true` — цена показывается как «от», `note` — подпись под названием модуля. |
| `modules[].qty` | Необязательно. Если указано — модуль считается поштучно (цена × количество), в калькуляторе появляется поле количества: `unit` (единица: строка или три формы для склонения, например `["язык", "языка", "языков"]`), `short` (краткая подпись у цены, например «стр.»), `label`, `min`, `max`, `default`. |
| `terms[]` | Сроки подписки: `months` и `discount` (0.25 = скидка 25% на ежемесячный платёж). |
| `defaultBase`, `defaultTerm` | Что выбрано по умолчанию. |
| `startPayment.months` | Стартовый платёж в месячных платежах (2 = первый и последний месяц). |
| `buyout.multiplier` | Базовая цена выкупа = `multiplier` × месячный платёж без скидки. |
| `buyout.creditShare` | Какая доля оплаченных подписок засчитывается в выкуп (0.3 = 30%). |
| `buyout.minMonths` | Минимальная цена выкупа = `minMonths` × месячный платёж без скидки. |
| `roundTo` | Округление сумм (100 = до сотен рублей). |

Формулы (они же показываются посетителю под расчётом):

```
Платёж без скидки = основа + Σ (цена модуля × количество)
Платёж в месяц    = платёж без скидки × (1 − скидка за срок)
Стартовый платёж  = startPayment.months × платёж в месяц   (первый и последний месяц)
Итого за срок     = платёж в месяц × месяцев               (стартовый платёж входит сюда)
Выкуп             = max(multiplier × платёж без скидки − creditShare × итого за срок,
                        minMonths × платёж без скидки)
```

Кнопка «Отправить расчёт» подставляет выбранную конфигурацию в форму заявки (поля «Что нужно» и «Кратко о задаче»), а структурированный расчёт сохраняется в заявке в поле `calc`.

Тексты страниц частично дублируют настройки: цифры «от 4 900 / 9 900 / 14 900 / 19 900 / 29 900 / 34 900 ₽», скидки 25% / 35%, сроки «3–7 дней» и «до 30 дней», условия выкупа 30% / 12× / 3×. Цены на карточках продуктов и в списках модулей на страницах услуг подтягиваются из `pricing.json` автоматически, остальные тексты (тарифы, FAQ, описания услуг) правятся в `site/` с последующей пересборкой (см. ниже).

## Страницы и сборка

Сайт многостраничный, адреса без `.html` (сервер сам отдаёт `/prices` → `public/prices.html`, старые адреса `*.html` перенаправляются 301):

| Адрес | Что на странице |
|---|---|
| `/` | оффер, как это работает, продукты, кратко о тарифах, готовых решениях и выкупе, заявка |
| `/services` и `/services/landing`, `/website`, `/shop`, `/web-app`, `/android`, `/desktop` | посадочные страницы услуг: что входит, сроки, цена, модули, FAQ, заявка с выбранным продуктом |
| `/prices` | тарифы, скидки, калькулятор (`/prices?base=shop#calc` — сразу с выбранной основой) |
| `/solutions` | каталог готовых решений и продажа своего проекта |
| `/solutions/simpleab`, `/l2start`, `/arm-game`, `/personal-vpn` | карточки готовых решений: галерея, цена, что входит, возможности, кнопки заявки |
| `/buyout` | выкуп, переуступка и продажа, сравнение с разработкой под ключ |
| `/faq` | «Вопросы»: все частые вопросы |
| `/privacy` | политика конфиденциальности |

Старые якоря одностраничной версии (`/#faq`, `/#calc` и т. п.) перенаправляются на новые страницы скриптом `public/assets/legacy-hash.js`.

**HTML-страницы в `public/` собираются генератором** — не правьте их вручную, иначе правки пропадут при следующей сборке:

- `site/build.js` — шапка, подвал, форма, главная и внутренние страницы, `sitemap.xml`;
- `site/services.js` — тексты страниц услуг (заголовки, описания, состав, модули, FAQ);
- `site/projects.js` — тексты готовых решений (описание, возможности, стек, скриншоты из `public/assets/projects/`); цены и адреса — в `public/assets/projects.json`;
- `site/partials/*.html` — крупные блоки: первый экран, тарифы, калькулятор, выкуп, сравнение, FAQ, готовые решения, форма заявки, политика.

После правок: `node site/build.js`, затем `docker compose up -d --build`.

## Структура

```
digitalsub/
├─ Dockerfile, docker-compose.yml, .dockerignore, .env.example
├─ package.json
├─ server.js                 # сервер: статика с чистыми адресами + POST /api/lead + GET /api/health
├─ site/                     # исходники страниц и генератор (node site/build.js)
├─ data/                     # заявки при запуске без Docker (leads.jsonl)
└─ public/                   # собранный сайт
   ├─ index.html, prices.html, solutions.html, buyout.html, faq.html, services.html, privacy.html
   ├─ services/*.html        # страницы услуг
   ├─ 404.html, robots.txt, sitemap.xml, site.webmanifest
   ├─ favicon.svg, favicon.ico, favicon-32.png, apple-touch-icon.png
   └─ assets/
      ├─ styles.css, main.js, legacy-hash.js
      ├─ pricing.json        # ← все цены калькулятора
      ├─ projects.json       # ← цены готовых решений и условия переуступки
      └─ og-image.png        # картинка для соцсетей и мессенджеров
```

## Перед публикацией

- Впишите реквизиты оператора персональных данных в `site/partials/privacy.html` (по 152-ФЗ) и пересоберите страницы.
- Добавьте контакты (Telegram, телефон, email) в подвал (`FOOTER` в `site/build.js`), если хотите показывать их открыто.
- На сервере поставьте перед контейнером nginx/Caddy с HTTPS для домена digitalsub.ru (сервер учитывает `X-Forwarded-For` для лимита заявок).
- По желанию подключите Яндекс Метрику (потребуется разрешить её домены в заголовке `Content-Security-Policy` в `server.js`).
